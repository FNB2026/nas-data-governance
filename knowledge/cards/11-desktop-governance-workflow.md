# 桌面治理闭环

NDG 桌面端的任务不是继续扩展“扫描 + 重复列表 + 诊断标签”的临时前端，而是把后端已有的目录语境、规划、隔离、清理与安全规则接成完整治理流程。重复内容只是事实证据；目录职责、存储用途、保护规则、人工复核与执行状态共同决定动作。

固定七域为：数据源、扫描任务、重复结果、治理复核、执行中心、审计与恢复、设置。不新增独立 Dashboard，不保留独立诊断一级入口。诊断结果回到对应业务场景；重复结果页只能送入复核，不能直接永久删除。

桌面写入链路必须保持分层：

```text
事实发现 → 治理复核 → DRAFT 计划 → APPROVED → dry-run
→ stale/保护/范围/隔离区/Journal 检查 → 执行 → 校验 → 审计/恢复
```

导航与按钮由项目模式、后端能力声明、执行准备状态和恢复锁共同决定。前端不得用错误字符串猜测业务状态，不得提交任意路径列表绕过计划，不得把项目治理状态只存在 localStorage。存在恢复锁时，审计与恢复优先，新扫描、计划编辑和新执行保持禁用。

实现顺序必须先冻结可运行基线，再建立 AppShell 与能力模型，然后依次接线数据源/扫描、重复证据、治理复核、执行、审计恢复与设置，最后做性能和发布打磨。每一阶段都保留当前可用链路，并分别验证 Go、race、vet、TypeScript、Vite 与 Wails 构建。
