# Mac App Store Phase 0 — local sandbox feasibility

Date: 2026-10-12 (Asia/Shanghai). Baseline main: `16e80a852b0b2e38785406cce565421fce0c5877`.
Existing GitHub Public Beta (published, immutable) product RC: `791f19119542e69b62ee62dd358fed188000837e` / v0.5.0-beta.11.

Decision: **technically feasible for the tested read-only core, conditional GO to adaptation design; NOT ready for App Store distribution**. No App ID was registered, no certificate/profile issued, no App Store Connect build uploaded, and no submission attempted. The existing DMG configuration and release artifacts remain separate.

## Audited existing architecture

- Go 1.26.9, Wails v2.13.0, React 18, modernc SQLite 1.56.0. Do not infer compatibility from the newer online Wails docs version alone.
- `cmd/ndg-desktop/build/darwin/Info.plist`: `com.fnb.ndg`, minimum macOS 13.0, marketing version 0.5.0, build 11. DMG uses Developer ID Application / hardened runtime, notarization and DMG staple.
- Existing entitlements have JIT / unsigned executable memory exceptions and **no App Sandbox**. They are untouched. The production-mode probe ran without those exceptions, without network.server, Downloads access or temporary sandbox exceptions. This proves only this local prototype's requirements.
- The production picker calls `runtime.OpenDirectoryDialog` and returns a string. There is no persistent security-scoped URL / bookmark or balanced per-job access lease. Merely adding sandbox entitlements is insufficient.
- `internal/project/service.go:DefaultSupportBase` uses `os.UserConfigDir()/NDG`. Inside the tested sandbox process, Go's config directory and Foundation's Application Support location both mapped into the prototype container. Foundation is used explicitly in the probe, and the probe refuses startup outside its expected container. Production import/export and all existing path entry points still need an access audit.
- The prototype uses the actual `app.NewScanService`, production scanner/fingerprint functions, SQLite migrations/store and checkpoint logic. Group counts are computed from persisted SHA-256 values in the probe; the production Duplicate Results GUI is not under test. It does not invoke the production Wails API or instantiate any execution service. Its React interface is a small separate frontend.
- Wails v2.13.0 has private inspector APIs under dev/debug/devtools build tags, so those modes must never be used for store builds. Its production source also uses KVC `drawsBackground`; this is an App Review/API compatibility risk to investigate with upstream. No acceptance promise or unsupported-API exemption is inferred.

## Separate configurations

- Prototype: `cmd/ndg-mas-probe`, bundle `com.fnb.ndg.mas.phase0`, version 0.0.1/build 1, ad hoc signed local sandbox bundle. It is deliberately not branded as a formal beta candidate.
- Proposed product MAS configuration: `cmd/ndg-desktop/build/mas/config.json` and `entitlements-readonly.plist`. Proposed `com.fnb.ndg.mas` is **not registered**. Configuration is design-only; distribution/upload disabled.
- Both use App Sandbox, user-selected read-only access, app-scoped bookmarks, network.client. No network.server or blanket source directory grants. Network.client is a conservative declared capability; its necessity for every mounted-SMB configuration has not been established by an entitlement subtraction experiment.
- Native Objective-C/Cgo bridge uses NSOpenPanel, read-only security-scoped bookmarks, resolution without automatic UI/mounting, start/stop access around reads, stale bookmark regeneration, and fixed redacted error classifications. The scope lease ends after selection persistence or the scan.
- Canonical path comparison handles macOS `/var` versus `/private/var` aliases. A resolved root relocation requires a new selection. This is a capability probe, not a reviewed general migration/volume-identity implementation.
- GUI emits counts/classifications only; raw bookmarks, paths and index metadata are private container data. Raw errors and file names are not returned to the frontend.

## Apple / Wails requirements checked on 2026-10-12

[Apple App Sandbox](https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox) requires sandboxing for Mac App Store distribution. [File access](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox) requires scoped URL access after resolving stored bookmarks. [Bookmark entitlement](https://developer.apple.com/documentation/professional-video-applications/enabling-security-scoped-bookmark-and-url-access) covers persistent app-scoped access. These support the bridge/lease design rather than arbitrary path-based reopening.

[Provisioning profile requirements](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile): explicit registered App ID, matching bundle/profile/distribution certificate. Local inventory has Developer ID and development identities, but no MAS application/installer distribution identities and no installed profile matching the proposed MAS or probe IDs (two installed profiles decoded). Local ad hoc success does not prove store signing.

[Apple upload documentation](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds) identifies bundle ID/version/build association and Xcode/Transporter/altool paths. Its current page has a 2026 Xcode 14+ uploader notice while its platform table retains older upload columns; do not treat the table as permission to ship with an obsolete uploader. Use a supported current stable toolchain and recheck immediately before a later authorized upload. This phase used Xcode 26.6, not an upload. [Upcoming requirements](https://developer.apple.com/news/upcoming-requirements/) include removal of quarantine xattrs **inside a store upload artifact**; this does not authorize bypassing Gatekeeper on users' DMGs.

[App Review 2.4.5](https://developer.apple.com/app-store/review/guidelines/#hardware-compatibility): sandbox, self-contained bundle, Apple packaging tooling, no unconsented residual processes, no feature-expanding code downloads. Store distribution needs an application distribution signature plus installer signing for a component PKG, matching embedded profile and validation. The [Wails MAS guide](https://wails.io/docs/guides/mac-appstore/) describes this packaging path, but its broad example entitlements are not copied blindly.

[Privacy manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files) and [required reason APIs](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api) require a separate inventory of Go/runtime/Wails/native file timestamps, disk space, boot-time and UserDefaults usage and applicable approved reasons. No manifest compliance claim is made here. Review 5.1.1 also requires an accessible policy and accurate App Store privacy answers. Existing local-only processing/no external AI default should be retained; network.client does not itself establish external transmission. Review needs explicit user selection, cancellation/reselection, disclosure of private bookmarks/DB records, retention/export, and a clear destructive-action safety model.

## Bundle ID / coexistence decision

| Option | Consequence | Recommendation |
|---|---|---|
| Keep com.fnb.ndg | Common logical identity but sandbox container differs from existing host Application Support; LaunchServices, bookmark identity, updater/replacement and DB double-writer ambiguity | Defer; needs signed transition/migration design and exclusive-DB ownership |
| Independent com.fnb.ndg.mas | Separate container, preferences/bookmarks and install identity; DMG and store can coexist; no implicit history import | Preferred for initial store adaptation |
| Shared App Group | Explicit group entitlement/profile and broader data-sharing surface; not an automatic bridge to current unsandboxed data | Not needed in Phase 0 |

No automatic migration. Future import must be user-selected from a closed independent backup, copy into the container, validate DB/version and all source grants, and retain originals. DB WAL/SHM and bookmarks cannot be assumed portable. Cross-bundle bookmarks should be recreated through native selection. Two versions must not execute against the same live DB/source concurrently.

## Quarantine / Restore impact (assessment only)

Read-only grants cannot support the existing copy/verify/delete or original-path restore workflow. A later, separately reviewed write phase needs distinct explicit read-write capabilities for source and quarantine roots, per-operation scope leases covering validation through Journal/write/verify/rollback, and capability revalidation on relaunch/remount. Approval of a plan is not an OS file grant. Returning authorization alone must never clear a durable recovery lock or resolve an uncertain partial output. Reject before file/DB execution effects when required capabilities are absent. Preserve existing protected-root, no-follow, stale, CAS, Journal and fail-closed checks. Purge backend release policy must remain independent of frontend capability flags; no store switch/environment override should enable it.
