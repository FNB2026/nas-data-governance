# ADR-0005：分级删除与隔离区永久清除

状态：已采纳

## 决策

新增 M7 删除生命周期：

1. `QUARANTINE` 仍是源目录执行器可执行的最高删除等级。
2. 隔离完成后必须从执行 Journal 建立受管 `quarantine_items` 台账。
3. 恢复采用独立的计划、摘要审批、只读预检、执行和恢复 Journal。
4. 保留期届满只生成单项 `PURGE DRAFT`。
5. 永久清除由隔离区专用执行器完成，不复用 `OperationDelete`，不接受源目录路径，不提供 `--all`。
6. PURGE 在同卷 staging 中第二次校验完整哈希；持久化 `commit_pending` 后才进入不可逆提交点。
7. 受保护项进入 `HOLD`，本版本不提供解除 HOLD 的自动化入口。

## 理由

永久删除没有提交后的文件级回滚能力，因此必须把“建议删除”“隔离”“到期候选”“审批”和“不可逆提交”建模成不同状态。独立 PURGE 执行器避免手工编辑普通 operation plan 后绕过隔离期，也让崩溃恢复能够明确区分提交前回滚与提交后对账。

## 后果

- 默认隔离保留期为 30 天，CLI 最低允许 24 小时。
- 审批摘要包含计划、隔离项、路径、哈希、大小和保留期证据。
- 永久清除只代表当前文件系统命名空间移除，不等同于存储介质安全擦除。
- 快照、备份和底层介质销毁必须由独立的存储基础设施流程管理。
