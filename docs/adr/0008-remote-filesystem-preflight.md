# ADR-0008：远程文件系统只读预检与保守扫描

- 状态：Accepted
- 日期：2026-08-13

## 背景

NDG 通过 macOS 文件系统访问用户选择的本地目录或已挂载 NAS。当 SMB、NFS、WebDAV 或 FUSE 类文件系统运行在高延迟、中继或不稳定网络上时，局域网默认假设不再成立：目录列举可能阻塞，inode 可能由客户端合成，挂载中断也不等于远端文件被删除。

Tailscale、VPN 或其他组网只是网络通道，不是 NDG 数据源协议。数据源仍应记录为用户已挂载的文件系统。

## 决策

1. 启动扫描前执行有界、只读预检：仅检查根目录、打开目录并请求最多一个条目；不打开文件、不遍历子目录、不跟随符号链接、不写源端。
2. 预检结果只暴露协议无关的能力信息：在线状态、文件系统类型、是否网络存储、物理身份是否可信、延迟和建议并发。普通诊断不包含路径、主机、账号或共享名。
3. SMB、NFS、AFP、WebDAV 和 FUSE 的 device/inode 默认不可信。上次与本次物理身份都可信且 device、inode、size、mtime 一致时，才能复用旧哈希。
4. 网络数据源的自动并发由预检给出：高延迟默认 1，其他网络文件系统默认 2；用户显式值在网络文件系统上不得超过 4。执行器不因扫描并发而放宽写入约束。
5. 扫描覆盖度显式为 `complete` 或 `partial`。只有完整遍历才能将未见路径标记为 `missing`；任何局部读取错误都使未见范围进入 `unavailable`，不得推断删除。
6. 远程数据源写入仍受现有独立执行器、审批、stale 检查、隔离、校验、审计和回滚边界约束。预检通过只允许扫描，不构成写入授权。
7. 网络文件系统出现断连、超时、stale mount 或 I/O 中断时，扫描任务进入终止型 `PAUSED_NETWORK` 状态，而不是 `COMPLETED` 或 `FAILED`。该状态表示当前后台协程已经安全退出，但保留可续扫检查点；恢复连接后由用户启动新的续扫任务。
8. 续扫边界按完成的目录前缀推进。只有该前缀内已提交的哈希任务结束、文件元数据写入项目数据库后，才更新检查点。目录列举一旦出现错误，本次扫描不再越过错误位置推进检查点，避免续扫跳过未读取条目。
   已列举文件在哈希阶段出现断连、stale mount 或挂载消失同样冻结检查点并进入 `PAUSED_NETWORK`；不得仅记为普通单文件哈希失败后宣称扫描完成。
9. 检查点只写入 NDG 项目数据库；不会在 NAS、Tailscale 节点或远程共享中创建辅助文件。
10. 网络源预检达到 250ms 时，桌面端明确提示高延迟并建议保持单并发，同时建议检查 VPN/Tailscale 是否处于中继路径。该提示只依据挂载文件系统实测延迟，不读取或记录组网产品的节点身份。

## 后果

- 高延迟 NAS 首次扫描可能更慢，但不会因为不可信 inode 而错用旧内容证据。
- 数据源页可以显示保守的扫描建议，不需要依赖 Tailscale CLI 或任何特定组网产品。
- 网络中断后的续扫可能重复处理最后一个未完成目录，这是为了保证不漏文件的保守选择。
- 本 ADR 不实现原生 WebDAV 客户端、Tailscale 管理、带宽自适应算法或远程写入协议；这些必须各自通过独立安全评审。
