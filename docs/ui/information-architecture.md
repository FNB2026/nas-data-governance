## 一级导航

沿用七个一级入口，不额外增加独立 Dashboard：

```
数据源
扫描任务
重复结果
治理复核
执行中心
审计与恢复
设置
```

项目摘要放在「数据源」顶部或应用首页，不单独占一级入口。

---

## 各页面职责

### 数据源

回答：打开的是哪个项目、数据来自哪里、哪些目录被保护、数据源是否在线、是否具备扫描条件、是否配置了隔离区。

布局：项目摘要 → 数据源卡片 → 扫描与保护策略 → 隔离区与执行准备状态。

### 扫描任务

左侧任务列表（运行中/已完成/已停止/失败），中间进度（阶段/文件数/已读容量/哈希候选/警告/持续时间），右侧参数（数据源/排除规则/worker数/增量或完整/检查点/失败摘要）。

全局进度区不显示完整路径、最近文件名、路径滚动日志。目录发现阶段不显示虚假百分比。

### 重复结果

三栏结构：左筛选与批量规则、中重复组列表、右证据与目录语境检查器。

列表列项：风险、文件代表名称、大小、路径数、物理副本数、硬链接标志、物理可回收上限、治理候选容量、目录角色数、业务锚点数、是否含保护项、复核状态、计划状态。

默认排序：治理候选容量降序 → 风险 → SHA-256。必须稳定排序。

### 治理复核

核心问题不是「删除哪个」，而是「这组相同内容在不同存储语境中分别承担什么职责」。

决策：保留全部、选择主要保留项、生成隔离草案、标记交叉归档、标记备份关系、暂缓处理、纠正目录角色、纠正业务锚点。

批量应用前必须显示影响数量并先预览，不直接提交。

### 执行中心

入口条件：APPROVED + 无未解决 REVIEW + 隔离区验证 + SourceRoots 验证 + Journal 可用 + 独立备份确认。

高风险执行要求输入包含实际数量的确认语句，不只是红色按钮。

容量同时显示：原始候选、dry-run 可执行、因 stale 阻止、因保护阻止、预计释放、实际完成。

### 审计与恢复

操作审计、执行 Journal、未完成执行、回滚记录、私有诊断、导出。

应用启动时先调 ListExecutingPlans / ListRecoverableRuns，若存在未完成执行则展示恢复提示并锁定新写操作。

### 设置

扫描（worker/重试/排除/跨挂载/增量默认）、隐私（路径显示/截图模式/导出脱敏/最近项目/错误详情）、性能（页大小/事件频率/只读连接数/缓存上限）、开发者（版本/commit/build time/schema/规则版本/诊断/日志）、AI与联网（明确显示外部AI关闭/遥测关闭/云上传关闭）。
