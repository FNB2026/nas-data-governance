## 1. 安装与首次启动

### 1.1 系统要求

- macOS 13.0 或更高版本
- 支持 Apple Silicon（M1/M2/M3/M4）和 Intel 处理器
- 需要读取权限访问待扫描的 NAS 或本地目录

### 1.2 安装方式

**DMG 安装（推荐）**：

1. 下载 `NDG-<版本号>-macos.dmg` 文件
2. 双击打开 DMG
3. 将 NDG 应用拖入"应用程序"文件夹
4. 首次启动时，macOS 可能提示"无法验证开发者"。前往"系统设置 → 隐私与安全性"，点击"仍要打开"

> 正式版 DMG 已通过 Apple Developer ID 签名和公证，Gatekeeper 会自动放行。Beta 版可能使用自签名证书。

### 1.3 首次启动

启动应用后，界面左侧为导航栏，右侧为内容区。首次使用时，"数据源"页面会显示项目创建卡片，引导你新建第一个项目。

应用启动时会自动加载以下信息：
- 版本信息（版本号、构建时间）
- 最近打开的项目列表（如有）

**界面导航**：

| 导航项 | 功能 |
|---|---|
| 数据源 | 项目管理、存储源注册、诊断 |
| 扫描任务 | 新建扫描、查看进度与历史 |
| 重复结果 | 查看重复文件组与详情 |
| 治理复核 | 生成、审查与批准治理计划 |
| 执行中心 | 执行计划、隔离恢复、永久清理 |
| 审计与恢复 | 查看操作日志、崩溃恢复 |
| 设置 | 路径脱敏、扫描参数、版本信息 |

## 2. 新建项目与选择扫描目录

### 2.1 创建项目

1. 在"数据源"页面，点击"新建项目"
2. 输入项目名称（用于标识，如"家庭NAS-2024"）
3. 点击"选择目录"，在系统对话框中选择要扫描的根目录
4. 点击"创建项目"

**创建过程中发生了什么**：

- 应用在 `~/Library/Application Support/NDG/projects/<项目ID>/` 下创建项目目录
- 生成 `governance.db` 数据库文件（权限 0600，仅当前用户可访问）
- 写入 `project.json` 项目元数据文件
- 注册扫描源（Storage ID 绑定到根路径，永不重绑定）
- 记录到最近项目列表

**扫描源验证规则**：

- 必须是真实存在的目录（不能是符号链接）
- 必须有读取和搜索权限
- 不能位于 NDG 应用支持目录内部
- 不能与已注册的扫描源重叠（嵌套关系会被拒绝）

### 2.2 打开已有项目

在"数据源"页面，从最近项目列表中选择一个项目打开。

**只读模式与读写模式**：

- **只读模式**：可以查看所有扫描结果、重复组、治理计划，但不能执行扫描、修改决策、批准计划或执行操作
- **读写模式**：拥有全部功能，包括扫描、审批和执行

> 如果只需要查看历史数据而不做更改，使用只读模式更安全。

### 2.3 就绪检查

打开项目后，"数据源"页面会显示就绪检查清单：

- 已注册存储源数量
- 已发现文件数量
- 读写模式状态
- 恢复锁状态（如有卡住的执行操作，会阻止新建扫描）
- 治理计划数量（可选）

## 3. 扫描、暂停与继续扫描

### 3.1 启动扫描

1. 进入"扫描任务"页面
2. 确认或修改扫描根目录（默认预填已注册的存储源路径）
3. 配置扫描选项：
   - **完整扫描**：开启后对所有文件计算完整 SHA-256（更精确但更慢）；关闭时使用快速采样哈希（头部和尾部各 64KB）
   - **工作线程数**：1-64，留空则自动检测（通常等于 CPU 核心数）
4. 点击"开始扫描"

扫描在后台异步执行，前端每秒轮询进度，显示：已发现文件数、已处理文件数、失败数。

### 3.2 扫描阶段

扫描包含四个阶段：

| 阶段 | 说明 |
|---|---|
| 遍历 | 以确定性字典序前序 DFS 遍历文件系统 |
| 快速哈希 | 并发计算快速指纹（采样头部和尾部各 64KB） |
| 完整哈希 | 仅对快速哈希相同的候选重复文件计算完整 SHA-256 |
| 持久化 | 写入数据库、标记缺失文件、更新检查点 |

**增量哈希复用**：如果文件的 `大小 + 修改时间 + inode` 均未变化，直接复用上次扫描的哈希结果，跳过重算。

### 3.3 暂停扫描

点击"取消扫描"按钮即可暂停当前扫描。

- 取消请求立即返回，不等待扫描实际停止
- 扫描引擎检测到取消信号后优雅退出
- 检查点被标记为 `aborted`（而非 `completed`），保留已扫描进度
- 作业最终状态显示为 `CANCELLED`

### 3.4 继续扫描

如果上次扫描被取消或因崩溃中断，"扫描任务"页面会检测到可恢复的检查点并显示"继续扫描"按钮。

- 从检查点记录的 `last_scanned_path` 恢复
- 已扫描的文件计数会累加，保证跨多次中断-恢复循环单调递增
- 检查点每 1000 个文件更新一次

**注意**：
- 恢复的正确性依赖文件系统的确定性遍历顺序。如果扫描期间目录结构发生重大变化（大量重命名/移动），建议使用"完整扫描"重新开始
- 如果存在更新的 `completed` 检查点，旧的 `aborted` 检查点不再可恢复
- 完整扫描模式（`FullScan=true`）忽略检查点，重新计算所有哈希

### 3.5 扫描排除规则

以下目录会被自动跳过，不参与扫描：

- `.data-governance-trash`（NDG 隔离区）
- `@eaDir`（Synology 缩略图目录）
- `.snapshot`（快照目录）
- `#recycle`（回收站目录）
- 所有符号链接（不跟随）
- 跨挂载点的子目录（默认不跨越，可通过配置开启）

### 3.6 网络断线处理

扫描 NAS 时如遇网络中断，前端会自动重连（最多 5 次指数退避重试）。重连成功后继续轮询进度；全部重试失败后显示连接错误。

## 4. 重复文件结果解释

### 4.1 查看重复组

扫描完成后，进入"重复结果"页面查看重复文件组。

**顶部汇总条**显示：
- 总重复组数
- 逻辑总量（所有重复副本占用空间之和）
- 可回收物理空间（实际可释放的空间）
- 硬链接别名字节（硬链接不占用额外空间，不可回收）

**左侧列表**：分页展示重复组（每页 20 组），可按存储源和最小可回收空间过滤。

**右侧详情**：点击某个组查看文件成员列表，包含路径、大小、修改时间、格式信息和物理身份（设备/Inode/链接数）。

### 4.2 哈希机制

- **快速哈希**：采样文件头部和尾部各 64KB 计算 SHA-256。文件小于 128KB 时直接计算全文。用于快速筛选候选重复
- **完整哈希**：对整个文件计算 SHA-256。仅对快速哈希相同的候选文件计算，用于最终确认

> 快速哈希存在极小概率误报（不同文件碰巧头部和尾部相同），完整哈希确保零误报。

### 4.3 硬链接识别

如果两个路径指向同一物理文件（相同 Device + Inode），NDG 会识别为硬链接而非重复副本。

- 硬链接不占用额外磁盘空间
- 可回收空间 = (物理副本数 - 1) × 文件大小
- SMB 等无稳定 inode 的网络协议下，每个路径保守地视为独立物理副本

### 4.4 文件关系

除了内容相同的重复文件，NDG 还识别以下关系：

- **版本链**：同目录内基础名相同、仅版本标记不同的文件（如 `report_v1.pdf` 和 `report_v2.pdf`）
- **派生对**：同目录、同基础名、不同扩展名的文件（如 `photo.jpg` 和 `photo.png`），仅限图像/视频/音频/文档类别
- **侧车链接**：元数据文件（如 `.xmp`、`.srt`）与其同目录中的主文件关联

> 这些关系默认不自动删除，仅提供参考信息辅助决策。

## 5. 目录语境与误删保护

### 5.1 什么是目录语境

NDG 根据文件所在的目录路径自动推断其"语境角色"，用于评估文件的重要性和保护级别。这一过程仅解读路径字符串，不触碰文件内容。

**10 种目录角色**（按权限从高到低）：

| 角色 | 权限 | 受保护 | 示例关键词 |
|---|---|---|---|
| 系统/应用 | 100 | 是 | `.git`、`docker`、数据库、系统、VM |
| 敏感 | 100 | 是 | 私密、个人、证件、医疗、财务、银行、密码、合同 |
| 备份 | 95 | 是 | backup、备份、冷备、快照、同步 |
| 原始素材 | 90 | 是 | raw、原始、母带、source、素材 |
| 正式归档 | 90 | 否 | 归档、存档、正式、已完成、档案、成品 |
| 项目工作 | 65 | 否 | 项目、project、客户、交付、剪辑、设计 |
| 未整理 | 45 | 否 | 未整理、待整理、杂项、inbox |
| 临时 | 20 | 否 | temp、tmp、临时、中转、下载、导出 |
| 缓存/衍生 | 10 | 否 | cache、缓存、缩略图、proxy、转码、渲染 |
| 未知 | 50 | 否 | （无匹配关键词） |

### 5.2 保护机制

**敏感词最高优先**：检测到"私密/个人/证件/医疗/财务/银行/密码/合同/法务/人事/身份证"等关键词时，立即标记为敏感目录，权限级别 100，受保护。

**受保护角色的文件**：
- 系统/应用、敏感、备份、原始素材角色的文件隔离后自动进入 HOLD 状态
- HOLD 状态的隔离项永远不会成为永久清理候选
- CRITICAL 风险的计划被冻结，无法通过常规审批流程

**学习规则限制**：内置保护规则权限为 90-100，学习规则权限上限为 60，永远无法覆盖保护规则。

### 5.3 文件格式保护

以下文件类型默认受保护，不会被自动清理：

- **项目源文件**：`.cpr`、`.sesx`、`.psd`、`.aep`、`.prproj`、`.lrcat`、`.step`、`.stp`、`.cdr`、`.cube`
- **元数据侧车**：`.xmp`、`.srt`、`.plist`
- **可再生缓存**：`.peak`、`.pkf`、`.pek`、`.cfa`、`.mpgindex`、`.lrprev`（受保护，但可在主资产验证后考虑清理）

> "内容相同不等于可删除"是 NDG 的核心原则。即使两个文件内容完全一样，如果它们位于不同职责的目录（如一个是原始素材，一个是临时缓存），系统也不会自动建议删除，而是标记为需要人工复核。

## 6. 执行计划、回滚与恢复

### 6.1 治理计划生命周期

NDG 的操作流程严格分为独立步骤，不可跳过：

```
扫描 → 分析 → 生成草案(DRAFT) → 审批(APPROVED) → 新鲜度检查(STALE_CHECKED) → 执行(EXECUTING) → 验证(VERIFIED)
                                    │                                                                    │
                                    └── 新鲜度失败 → DRAFT                                                └── 回滚(ROLLED_BACK)
```

### 6.2 生成与审批计划

1. 在"治理复核"页面点击"生成草案"
2. 系统根据重复组自动生成 DRAFT 状态的计划，包含建议操作（KEEP/MOVE/DELETE/QUARANTINE/REVIEW）
3. 查看计划详情：风险级别、证据列表、操作动作、目标路径、语境角色
4. 记录复核决策（全部保留/起草动作/暂缓/拒绝建议/交叉归档/备份关系）
5. 对非 CRITICAL 风险的 DRAFT 计划点击"批准"转为 APPROVED

**风险级别**：

| 风险 | 条件 | 处理 |
|---|---|---|
| CRITICAL | 缺少完整哈希、包含项目源文件/侧车/缓存、副本在受保护目录 | 全部 REVIEW，被冻结无法常规审批 |
| HIGH | 副本目录角色不同、业务锚点不同 | 全部 REVIEW，需人工确认 |
| MEDIUM | 全部在临时/缓存目录 | QUARANTINE（保留评分最高的 KEEP） |

**保留评分**：系统根据目录权威等级、文件年龄、路径深度和角色加分自动计算保留优先级。同分时更旧的文件优先保留。

### 6.3 执行计划

1. 进入"执行中心"页面，选择"计划执行"标签
2. 勾选已批准（APPROVED）的计划
3. 填写隔离根目录（隔离文件的存放位置）和源根目录
4. **先执行"试运行"**（dry_run）：仅验证不写文件，检查所有文件的新鲜度
5. 试运行通过后，点击"执行选中计划"

**执行安全管线**：

- **新鲜度检查**：执行前对每个文件校验大小、修改时间、inode、设备和 SHA-256。发现任何变化则计划退回 DRAFT，不执行任何写入
- **操作日志**：每个文件操作在执行前写入 pending 日志，执行后标记 done
- **复制-验证-删除**：所有移动操作遵循"先复制 → 验证 SHA-256 → 删除源文件"三步管道，验证失败时保留源文件

### 6.4 隔离与恢复

**重要**：NDG 中的"删除"操作实际上是"隔离"（移动到隔离区），不是永久删除。

**隔离区**：
- 隔离文件存放在你指定的隔离根目录下
- 隔离项有保留期（最低 24 小时），过期前不可永久清理
- 受保护目录的文件隔离后自动进入 HOLD 状态

**恢复操作**：
1. 在"执行中心"选择"隔离与恢复"标签
2. 选择要恢复的隔离项
3. 创建恢复计划 → 批准 → 试运行 → 执行恢复
4. 文件从隔离区移回原始路径（目标路径不能已存在文件）

### 6.5 永久清理

永久清理是独立的三步流程：

1. **创建清理计划**：系统查询过期且非 HOLD 的隔离项，生成 DRAFT 清理计划
2. **审批**：批准清理计划
3. **执行**：
   - 必须先通过试运行（dry_run）
   - 需要逐字输入系统生成的确认语句（如"确认永久清理隔离区中的 3 个文件，共 1572864 字节"）
   - 执行采用暂存管道：重命名到暂存目录 → 二次 SHA-256 验证 → 不可逆删除

> 永久清理是不可逆操作。清理前请确认你不再需要这些文件。

### 6.6 崩溃恢复

如果应用在执行操作期间崩溃：

- **启动时自动检测**：应用启动时自动查找所有非终态作业和执行中计划
- **保守策略**：
  - 已部分执行的计划 → 反向回滚所有已完成操作
  - 未开始执行的计划 → 重置为 APPROVED，允许重新执行
  - 歧义状态（如崩溃后文件可能已被重建）→ 拒绝自动决策，标记为需要人工介入
- **恢复锁**：检测到卡住的执行操作时，应用自动锁定，阻止新建扫描和执行操作。需在"执行中心"或"审计与恢复"页面处理恢复后解锁

## 7. 数据库位置、备份与迁移

### 7.1 数据库位置

NDG 的项目数据库存储在 macOS 应用支持目录：

```
~/Library/Application Support/NDG/projects/<项目ID>/
├── governance.db      # SQLite 数据库
├── governance.db-wal  # WAL 日志（运行时存在）
├── governance.db-shm  # 共享内存（运行时存在）
└── project.json       # 项目元数据
```

最近项目列表存储在：

```
~/Library/Application Support/NDG/recent.json
```

### 7.2 数据库安全

- 数据库文件权限：`0600`（仅所有者可读写）
- 数据库目录权限：`0700`（仅所有者可访问）
- SQLite 使用 WAL 模式保证崩溃一致性
- 写入使用 `txlock=immediate` 前置获取锁，避免中途锁定
- 单连接模式（`SetMaxOpenConns(1)`）避免锁竞争
- 打开数据库时拒绝符号链接
- 存储 ID 绑定到根路径，永不重绑定到不同目录

### 7.3 备份

NDG 目前不提供自动备份功能。建议手动备份方法：

1. 关闭项目（确保 WAL 已 checkpoint）
2. 复制整个项目目录：
   ```bash
   cp -R ~/Library/Application\ Support/NDG/projects/<项目ID>/ ~/Backups/NDG-<项目ID>-$(date +%Y%m%d)/
   ```
3. 恢复备份时，将目录复制回原位置即可

> 备份的数据库可以通过只读模式打开查看，不会修改原始数据。

### 7.4 迁移

**迁移到新 Mac**：

1. 复制 `~/Library/Application Support/NDG/` 整个目录到新 Mac 的相同位置
2. 确保扫描源目录在新 Mac 上可通过相同路径访问（或使用软链接映射）
3. 打开 NDG，从最近项目列表中选择项目

**注意**：Storage ID 绑定到根路径。如果扫描源路径发生变化（如 NAS 挂载点不同），需要创建新的项目并重新扫描。

### 7.5 只读模式打开

如果只需要查看数据而不做更改，可以用只读模式打开数据库：

- 只读模式使用 `mode=ro` 打开，不应用迁移
- 可以查看所有扫描结果、重复组、治理计划
- 不能执行扫描、修改决策、批准计划或执行操作

## 8. 常见错误与故障排查

### 8.1 扫描问题

**扫描启动失败：权限不足**

确保扫描根目录有读取和搜索权限。在终端中检查：
```bash
ls -la /path/to/scan/root
```
如果权限不足，使用 `chmod` 或在 Finder 中调整权限。

**扫描速度很慢**

- 确认未开启"完整扫描"（完整扫描对所有文件计算 SHA-256）
- 降低工作线程数（NAS 设备在高并发下可能反而更慢）
- 检查网络连接是否稳定（NAS 场景）
- 大量小文件会显著降低扫描速度，这是正常的

**扫描中断后无法继续**

- 检查是否存在 `completed` 状态的检查点（会覆盖旧的 `aborted` 检查点）
- 如果目录结构发生重大变化，建议使用完整扫描重新开始
- 查看任务详情中的事件历史，确认中断原因

**部分文件扫描失败**

- 单个文件读取失败不会中止整个扫描
- 失败计数显示在进度面板中
- 常见原因：权限不足、文件被锁定、网络中断
- 详细错误信息可在任务详情中查看（路径已脱敏）

### 8.2 执行问题

**执行计划失败：Stale 文件**

执行前的新鲜度检查发现文件在计划生成后发生了变化。这是安全机制：
- 计划会自动退回 DRAFT 状态
- 重新扫描后再次生成计划即可

**恢复锁激活**

检测到卡在 EXECUTING 状态的计划时，应用会自动锁定：
1. 进入"执行中心"或"审计与恢复"页面
2. 查看恢复锁状态和卡住的计划
3. 执行恢复操作（回滚或重置）
4. 恢复完成后锁自动解除

**隔离恢复失败：目标已存在**

恢复操作要求目标路径不存在文件。如果原路径已有文件（可能是崩溃后重建），需要：
- 手动处理冲突文件
- 或选择将隔离文件恢复到其他位置

### 8.3 数据库问题

**数据库锁定**

- 确保没有其他 NDG 实例同时打开同一项目
- 如果异常退出后无法打开数据库，尝试删除 WAL 和 SHM 文件：
  ```bash
  rm ~/Library/Application\ Support/NDG/projects/<项目ID>/governance.db-wal
  rm ~/Library/Application\ Support/NDG/projects/<项目ID>/governance.db-shm
  ```
  然后重新打开项目

**数据库损坏**

如果数据库损坏且无备份，需要创建新项目并重新扫描。损坏的数据库文件可以尝试用 SQLite 工具修复：
```bash
sqlite3 governance.db ".recover" > recovered.sql
sqlite3 new.db < recovered.sql
```

### 8.4 应用问题

**应用无法启动**

- 确认 macOS 版本 >= 13.0
- 如果 Gatekeeper 阻止启动：系统设置 → 隐私与安全性 → 点击"仍要打开"
- 查看崩溃日志：`~/Library/Logs/DiagnosticReports/`

**路径显示不完整**

在"设置"页面开启"路径脱敏模式"后，界面中的路径会被部分遮蔽。关闭此选项可显示完整路径。

## 9. 隐私、安全与数据不上传声明

### 9.1 完全本地运行

NDG 是一个完全本地运行的应用程序：

- **无网络请求**：代码中不存在任何 HTTP 客户端、远程调用或网络通信逻辑
- **无遥测**：不收集任何使用统计、崩溃报告或性能数据
- **无云上传**：不会将你的文件、文件名、路径、哈希值或任何元数据上传到任何服务器
- **无外部 AI**：外部 AI 功能默认关闭且不可配置

所有数据处理（扫描、哈希计算、重复检测、治理规划）均在你的 Mac 本地完成。

### 9.2 数据存储安全

- 项目数据库使用 `0600` 权限（仅所有者可读写）
- 项目目录使用 `0700` 权限（仅所有者可访问）
- 数据库中可能包含真实路径、文件名和哈希值，因此权限加固不依赖系统默认 umask
- 打开数据库时拒绝符号链接，防止路径注入

### 9.3 日志脱敏

- 审计日志仅记录抽象信息（字节数、错误类型、操作状态），不包含文件路径或内容
- 扫描错误摘要格式为"N non-fatal errors; paths omitted"，路径仅在私有诊断层可用
- 路径脱敏模式开启后，界面中的路径部分遮蔽，适合截图分享

### 9.4 文件系统安全

- **默认只读**：扫描、分析、规划全程只读，唯一可写层（executor）严格隔离
- **不跟随符号链接**：扫描器、数据库、执行器全链路拒绝符号链接
- **不跨挂载点**：默认不跨越挂载点扫描（可配置开启）
- **不越界**：所有文件操作限制在任务根目录内

### 9.5 操作安全

- **隔离而非删除**：所有"删除"操作实际上是移动到隔离区，可恢复
- **复制-验证-删除管道**：文件移动遵循"先复制 → SHA-256 验证 → 删除源"三步，验证失败保留源文件
- **新鲜度检查**：执行前校验文件大小/时间/inode/设备/哈希五维一致性
- **审批摘要绑定**：清理计划绑定 approval_digest，篡改内容则审批失效
- **受保护目录自动 HOLD**：敏感/原始/备份/系统目录的文件隔离后永不自动清除
- **崩溃保守恢复**：宁可回滚也不自动继续部分执行；歧义状态拒绝自动决策

### 9.6 公共仓库边界

NDG 是开源软件。仓库中有 CI 强制执行的公共边界检查，确保：
- 无凭证、令牌、私钥进入版本库
- 无用户路径、数据库文件、日志文件被跟踪
- 无敏感产物（.db、.jsonl、.log 等）进入版本库

### 9.7 你的数据属于你

NDG 不会：
- 上传你的文件或文件名
- 上传你的目录结构
- 上传你的哈希值或元数据
- 发送崩溃报告或使用统计
- 连接任何外部服务器

你的所有数据——扫描结果、治理计划、执行日志、隔离文件——都存储在你的 Mac 本地，完全由你控制。
